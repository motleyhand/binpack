binpack {{ .Chart.AppVersion }} is installed in namespace {{ .Release.Namespace }}.

{{ if .Values.config.dryRun -}}
It is in DRY RUN: it decides everything and changes nothing.

Watch what it would do:

  kubectl -n {{ .Release.Namespace }} logs -l app.kubernetes.io/name={{ include "binpack.name" . }} -f

Every decision also lands as an Event on the node itself, which needs no access
to binpack's logs at all:

  kubectl describe node <node> | sed -n '/^Events:/,$p'
{{- else -}}
It is configured to ACT (dryRun: false). It will cordon nodes, evict pods
through the eviction API, and annotate nodes with drain state. It deletes
nothing — the cluster-autoscaler removes the emptied node.

Watch what it does. Draining is a drain starting, Drained is one the
cluster-autoscaler finished, DrainAbandoned carries the sentence saying what
stopped it:

  kubectl get events -A --sort-by=.lastTimestamp \
    --field-selector reason=Draining

Set config.dryRun=true to go back to deciding without acting. A drain already in
progress is then left exactly as it is, cordoned and marked, rather than being
advanced or undone.
{{- end }}

binpack reads the cluster-autoscaler's status from one object, and its Role for
reading it is bound in that namespace:

  {{ include "binpack.autoscalerNamespace" . }}/cluster-autoscaler-status

The autoscaler publishes into the namespace it runs in, so if yours is somewhere
else binpack will report that none is running and refuse to act. Check where:

  kubectl get configmap cluster-autoscaler-status -A

then helm upgrade with config.discovery.autoscalerNamespace set to that namespace.

Before trusting it, ask what is stopping this cluster shrinking today:

  kubectl -n {{ .Release.Namespace }} exec deploy/{{ include "binpack.fullname" . }} -- binpack diagnose

That works without binpack installed at all, and usually finds something the
autoscaler is blocked on too.
{{ if not .Values.rbac.allowDraining }}
RBAC grants read and report only. rbac.allowDraining=true adds the cordon and
eviction verbs; set it together with config.dryRun=false to let binpack act.
The chart refuses one without the other.

  docs/how-to/let-binpack-drain-nodes.md
{{- end }}
